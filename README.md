# Khao Kheow Trip Planner

ต้นแบบเว็บภาษาไทย React + TypeScript + Vite สำหรับจัดแผนเที่ยวสวนสัตว์เปิดเขาเขียว ใช้ภาพจริงและแผนที่จากแหล่งทางการ ไม่มี backend บัญชีผู้ใช้ หรือฐานข้อมูลจริง และยังไม่ใช่ระบบนำทาง

## ติดตั้งและรัน

ใช้ Node.js **22.12 ขึ้นไป** (ตรวจรุ่นนี้ด้วย Node.js 24.12) และ npm รุ่นที่มากับ Node.js

```sh
npm ci --cache .npm-cache
npm run dev
```

เปิด URL ที่ terminal แสดง ปกติ `http://127.0.0.1:5173/` หากพอร์ตถูกใช้อยู่ Vite จะเลือกพอร์ตถัดไป แก้โค้ดแล้ว dev server จะอัปเดตอัตโนมัติ หากยังเห็นรุ่นเก่าให้กด Ctrl+Shift+R

```sh
npm test
npm run build
npm run preview
```

`npm test` ตรวจ flow ผ่าน DOM จำลอง ส่วน `npm run build` ตรวจ TypeScript และสร้าง `dist/` หลังแก้ไฟล์ต้อง build ใหม่ก่อนใช้ preview (ปกติพอร์ต 4173) หาก npm รุ่นเก่าใน PATH แจ้ง `edgesOut` ให้ใช้ npm ที่มากับ Node.js รุ่นปัจจุบัน ไม่ต้องลบประวัติ Git หรือเปลี่ยนแพ็กเกจโดยเดา

## ฟีเจอร์ที่ทำงานได้

- หน้าแรกใช้รูปจริง เลือกความต้องการ เช่น เดินน้อย ผู้สูงอายุ รถเข็น และเด็ก
- เลือกจุดที่มีภาพจริง 7 รายการ หรือค้นหา 99 จุด/กรอง 8 หมวดจากข้อมูลทางการ เพิ่มจุดจากรายละเอียดได้
- เพิ่ม ลบ เลื่อนลำดับ และตั้งจุดแรกของแผนได้ ความต้องการแสดงเป็นแท็ก ไม่ได้คำนวณระยะเดินหรือเส้นทางที่รองรับรถเข็น
- ดูภาพแผนที่ทางการ ซูม/เลื่อนได้ หมุด 9 จุดอ้างอิงตำแหน่งบนภาพที่ตรวจเทียบด้วยสายตาแล้ว อีก 90 จุดระบุ “ตำแหน่งรอยืนยัน” และไม่มีหมุดที่วางขึ้นเอง
- QR สร้างในอุปกรณ์ เปิดรายละเอียดด้วย `/#/point/official-54` เป็นต้น เลือกจุดและดาวน์โหลด PNG ได้ การสแกนข้ามเครื่องต้องใช้ URL ที่โทรศัพท์เข้าถึงได้ QR ของ localhost จะเปิดข้ามเครื่องไม่ได้ ยังไม่ใช่ป้ายติดตั้งจริงในสวนสัตว์
- GPS ขอสิทธิ์เฉพาะเมื่อกดปุ่ม ไม่บันทึกหรือส่งพิกัด ยังไม่วางตำแหน่ง GPS บนภาพแผนที่และไม่นำทาง ต้องใช้ HTTPS หรือ localhost ที่เบราว์เซอร์รองรับ
- บันทึก/เปิดกลับ/ลบแผนผ่าน localStorage ในเบราว์เซอร์เดิม เก็บรายการ ลำดับ ความต้องการ และเวลาบันทึก ไม่ซิงก์ข้ามเครื่อง

**ยังไม่รองรับเปิดเว็บใหม่แบบ offline:** ไม่มี Service Worker หรือการดาวน์โหลดแผนที่สำหรับ offline การบันทึกแผนไม่ได้หมายถึงเก็บตัวเว็บทั้งชุด ข้อมูลอาจหายเมื่อผู้ใช้ล้างข้อมูลเบราว์เซอร์

## ข้อมูลที่ยืนยันได้และสิ่งที่ยังรอยืนยัน

| ชนิดข้อมูล | สถานะ/ขอบเขต |
| --- | --- |
| ภาพแผนที่ ชื่อจุด 99 รายการ หมวด 8 หมวด และรูปจริง 7 ภาพ | snapshot จาก [หน้าแผนที่ทางการ](https://khaokheow.zoothailand.or.th/map) บันทึกเมื่อ 31 ตุลาคม 2569 ไม่ใช่ข้อมูลสด |
| `observed_in_official_source` | พบชื่อ/หมวดในแหล่งทางการ ไม่ยืนยันการเปิดบริการปัจจุบันหรือสิทธิ์เข้าพื้นที่ของนักท่องเที่ยว |
| `map_visual_checked` | ตรวจเทียบชื่อ/สัญลักษณ์และ x/y บนภาพแผนที่เดิม 9 จุด ไม่ใช่ latitude/longitude หรือผลสำรวจหน้างาน |
| `locationStatus: pending` | ตำแหน่งรอยืนยัน แสดงเฉพาะในรายการ ไม่วางหมุด |
| ลำดับแผน คำโปรย และแท็กความต้องการ | ข้อมูล/พฤติกรรมของต้นแบบ โดยแผนมีป้าย “ข้อมูลตัวอย่าง—รอยืนยันกับสวนสัตว์” ไม่ใช่คำแนะนำเส้นทางจริง |
| เส้นทาง ระยะทาง เวลาเดิน เวลาแสดง คิว และข้อมูลรถเข็น | รอยืนยันทั้งหมด ไม่มีการคาดเดาหรือเพิ่มพิกัดจริง ทุกจุดใน snapshot ปัจจุบันมี `lat/lng: null` |

แผนผัง SVG และจุด `demo-*` เดิมถูกแทนที่แล้ว ไม่ใช้แผนที่จำลองเก่า ไม่แสดงเส้นเชื่อมสมมติเป็นทางเดินจริง ลิงก์เดิมจะแจ้งว่าไม่พบจุดในฉบับปัจจุบัน แผน localStorage รุ่นเดิมไม่ถูกนำมาใช้ปะปนกับจุดทางการ

เวลาแสดงที่พิมพ์อยู่ในภาพเป็นข้อมูลตามฉบับภาพ ไม่ได้นำมาใช้คำนวณแผนและไม่รับรองรอบในวันที่เดินทาง หมวดพื้นที่อนุรักษ์มีพื้นที่งานภายในด้วย การมีชื่อบนแผนที่ไม่ได้หมายความว่าเข้าชมได้

## ไฟล์หลักและการอัปเดตข้อมูล

- `src/App.tsx` — flow หน้าแรก/ความต้องการ/จุดสนใจ/แผน/แผนที่/QR/GPS
- `src/ZooMap.tsx`, `src/Photo.tsx`, `src/styles.css` — ภาพแผนที่ ภาพจริง รูปแบบ responsive และ fallback
- `src/data/official-snapshot.json` — ข้อมูลต้นทางและ URL ภาพ
- `src/data/points.ts`, `official-map.ts`, `map-review.ts` — ข้อมูลสำหรับแสดงผล ขอบเขตสิทธิ์ และบันทึกตรวจตำแหน่งบนภาพ
- `tests/`, `vitest.config.ts` — การทดสอบ flow ที่รันด้วย `npm test`

`node scripts/fetch-official.mjs` ใช้ดาวน์โหลดจากแหล่งทางการและเขียนทับ snapshot/รูปในโปรเจกต์ **ไม่จำเป็นสำหรับติดตั้งหรือรันเว็บ** ใช้เฉพาะเมื่อจะอัปเดตข้อมูลและมีเครือข่าย/สิทธิ์ที่เหมาะสม สคริปต์บันทึกวันที่ตาม Asia/Bangkok และ hash ภาพ หากภาพหรือ x/y ของจุดเปลี่ยน หมุดที่เคยตรวจไว้จะกลายเป็นรอยืนยัน ต้องเปิดภาพตรวจใหม่ก่อนปรับ `map-review.ts` ห้ามคัดลอกพิกัดภาพไปอ้างว่าเป็น GPS

## ผลตรวจและข้อจำกัด

ดู [บันทึกการตรวจ](docs/REVIEW.md) มีการทดสอบ DOM สำหรับ flow ที่ค่า window width 390 และ 1366 พิกเซล ตรวจไฟล์ภาพ และ production build แต่ **jsdom ไม่ได้วาดหน้าจอหรือคำนวณ layout** จึงยังไม่ได้ยืนยันภาพหน้าจอมือถือ/คอมพิวเตอร์ครบทุกหน้า ยังไม่ตรวจข้อความล้นด้วยสายตา สแกน QR ด้วยกล้อง หรือ GPS/permission prompt จริง ไม่ถือว่า test/build ผ่านแทนการตรวจบนอุปกรณ์จริง

ไม่ต้องใช้ API key ไม่มีระบบล็อกอินหรือฐานข้อมูล และไม่มี API ภายนอกถูกเรียกขณะใช้งานปกติ (นอกจากเปิดลิงก์ทางการเมื่อผู้ใช้กดเอง)
